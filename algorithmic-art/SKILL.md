# Algorithmic Art

Use this skill to create original generative artwork as a working p5.js artifact. The output should include a concise algorithmic philosophy and a self-contained HTML viewer built from the bundled template.

The process has two linked parts. First, define the computational aesthetic: what system is being modeled, which forces or rules drive it, how variation appears, and which parameters matter. Then implement that aesthetic directly in code so the artwork is generated by reproducible behavior rather than by static decoration.

## Algorithmic Philosophy

Before writing code, produce a short philosophy of four to six paragraphs. Name the movement in one or two words, then describe the computational logic: noise fields, particle systems, recursion, harmonic motion, stochastic relaxation, geometry, feedback, or any other standard generative mechanism that fits the request.

The philosophy should guide implementation without becoming a script. It must identify the system's visual language, the source of variation, the role of time or iteration, and the parameters that a viewer should be able to explore. Avoid repeated claims about craft or beauty; precision is more useful than insistence.

The user's topic should become a subtle conceptual seed inside the system. Someone who knows the reference may recognize it through behavior, rhythm, parameter choices, or visual structure, while the piece still works as original generative art.

## Implementation

Read `templates/viewer.html` before writing HTML. Use it as the starting point, preserving the fixed layout, sidebar structure, seed controls, action controls, fonts, and visual framing. Replace only the variable sections: the p5.js algorithm, the parameters object, parameter controls, and optional color controls.

Seeded reproducibility is mandatory:

```javascript
let seed = 12345;
randomSeed(seed);
noiseSeed(seed);
```

Design parameters from the system itself. Useful parameter classes include counts, scale, velocity, density, thresholds, probabilities, angular behavior, force strengths, relaxation rates, and palette controls. Do not offer generic pattern choices when the algorithm can expose meaningful controls.

The viewer must be a single HTML artifact. It may load p5.js from a CDN, but the algorithm, state, controls, styling, and handlers should be inline. The seed display, previous seed, next seed, random seed, direct seed input, regenerate, reset, and PNG download controls must work. When the user requests many variations, use seed navigation or seed presets instead of creating many disconnected files.

## Quality Standard

The same seed must produce the same image. The composition should have controlled complexity, coherent color, readable hierarchy, and acceptable performance for the intended mode. If animated, it should run smoothly; if static, it should resolve to a deliberate final frame. Every artwork needs its own algorithm and parameter set.

Use `templates/generator_template.js` only as a structural reference for seeded randomness, parameter organization, and p5.js code shape. Do not copy its example as the artwork.

## Visual Harness

Before delivery, open the HTML artifact in a browser when tooling is available. Capture at least one rendered screenshot, check that the p5 canvas is nonblank, and verify that seed navigation, parameter controls, reset, regenerate, and PNG download work. For animated pieces, wait for several frames before judging the render. For responsive artifacts, inspect both a desktop and a mobile viewport.

If browser execution is unavailable, leave the exact command or file path needed to open the artifact and state which visual checks remain pending. Do not claim the artwork works from source inspection alone.

## Deliverables

Return the algorithmic philosophy, the final HTML artifact, and the visual harness evidence or pending checks. If files are written locally, also provide the relevant paths. The artifact should open in a browser without a build step.
